# moneybook

나 혼자 쓰는 복식부기 가계부. 왼쪽(차변)·오른쪽(대변)을 한 줄로 입력하면 잔액·자산현황·손익이 자동으로 도출되는 복식부기 방식을 직접 구현합니다.

## 기술 스택

- Next.js 16 (App Router) + TypeScript
- Drizzle ORM + libSQL (로컬은 SQLite 파일, 배포는 Turso)
- Tailwind CSS
- Auth.js v5 (Google / Naver)
- Vitest (단위 테스트) + Playwright (E2E)
- 자체 경량 i18n (한국어 / English)
- PWA (홈화면에 추가하면 주소창 없이 실행)

## 시작하기

```bash
npm install
cp .env.example .env.local   # 필요한 값 채우기 (로컬은 대부분 비워둬도 됨)
npm run dev
```

기본적으로 로컬 SQLite 파일(`./moneybook.db`)을 사용합니다. `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN`을 설정하면 원격 Turso DB로 전환됩니다.

배포는 [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)를 따라가면 됩니다 (Turso + Vercel + Google OAuth).

## 백업 (CSV)

설정 화면에서 네 종류를 내보내고 가져올 수 있습니다. 이 넷이면 가계부 전체가 복원됩니다.

| CSV      | 내용                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 계정과목 | 분류, 이름, 통화, 사용 기간(`activeFrom`/`activeTo`), 메모, 상위 그룹        |
| 거래     | 분개선 한 줄 = CSV 한 행, `transactionKey`로 거래 단위 그룹핑 (줄 메모 포함) |
| 예산     | 계정 이름 · 연월 · 금액                                                      |
| 환율     | 날짜 · 통화쌍 · 환율 · 출처 (수동 보정값은 API로 복원할 수 없으므로 포함)    |

가져오기는 **미리보기 → 확정** 2단계입니다. 미리보기에서 신규/기존/오류 건수와 오류 사유를 보여주고, 확정할 때만 씁니다. 거래는 커밋 전에 `assertBalanced`를 통과해야 하며, 균형이 맞지 않는 거래는 그 거래만 건너뛰고 나머지는 정상 반영됩니다. 첫 줄은 반드시 헤더여야 하고, 열 이름이 다르면 파일 전체를 거부합니다.

**용량**: 업로드 한도는 32MB(`next.config.ts`의 `serverActions.bodySizeLimit`)로, 10~15년치 일일 가계부를 한 파일로 복원하기에 충분합니다. 내보내기는 스트리밍이라 크기 제한이 없습니다.

단, **Vercel에 배포한 경우 요청 본문 4.5MB 제한**이 별도로 걸립니다. 이건 플랫폼 인프라 한도라 앱 설정으로 못 올립니다([문서](https://vercel.com/docs/functions/limitations)). 대략 3만 건이 넘는 거래를 복원하려면 파일을 나눠서 가져오거나, Node 서버로 자체 호스팅하면 32MB 한도가 그대로 적용됩니다.

### 한 줄 거래 CSV로 옮겨오기

다섯 번째 가져오기 폼은 이 앱 형식이 아니라 **한 행에 거래 하나가 통째로 담긴 CSV**를
그대로 읽습니다 (`날짜,아이템,금액,기간내합계,왼쪽,,오른쪽,,메모`). **한 행이 곧 한
거래**라 좌·우가 이미 한 줄에 다 있고, 여기서는 그게 분개선 두 줄이 됩니다.

- 파일이 이름만 대는 **계정은 자동으로 만들어집니다**(분류는 파일에 적힌 그대로,
  통화는 섹션 기준통화). 이미 있는 이름은 재사용하되, 분류가 다르거나 기준통화가
  아닌 계정이면 **그 계정을 쓰는 행을 전부 건너뛰고** 계정 단위로 한 번만 알려줍니다.
- **금액이 음수인 행은 왼쪽·오른쪽을 맞바꿔** 넣습니다. 이 앱은 방향을 `side`에
  담고 음수 금액을 금지하므로, 부호를 좌우로 접는 것이 같은 분개를 표현하는 유일한
  방법입니다.
- `기간내합계`는 **버립니다** — 내보낸 기간에서만 맞는 러닝 합계이고, 잔액은 언제나
  분개선에서 다시 계산합니다.
- `순자산`은 `자본`으로 들어가되, 거래 구분은 `normal` 그대로입니다. 순자산은
  분류지 거래 구분이 아니라서, `기초`로 찍어버리면 진짜 자본 거래를 잘못 이름
  붙이게 됩니다.

**기간을 book 시작일까지 늘려서 내보내세요.** 이런 내보내기는 흔히 최근 몇 년
구간이 기본이고, 그 앞의 잔액은 파일 어디에도 없습니다. 구간만 가져오면 그 구간의
증감은 정확하지만 출발점이 0이 됩니다.

## 설계 메모

- 모든 거래는 왼쪽(차변)·오른쪽(대변) 분개선(`transaction_lines`)의 합이 항상 같아야 합니다. 이 불변식은 `lib/ledger.ts`의 `assertBalanced`가 모든 저장 경로에서 강제합니다.
- **계정 목록과 파생 사실은 다르게 다룹니다.** 계정과목은 차원(카탈로그)이고, 잔액·플로우는 `transaction_lines`에서 나온 사실입니다. 계정의 사용 기간(`active_from`/`active_to`, `lib/accounts.ts`)은 **카탈로그만** 거릅니다 — 입력 폼의 계정 선택, 예산 행, 계정과목 목록. 잔액은 수준(level)이라 올해 거래가 없던 예금도 잔액을 그대로 들고 있고, 사용 기간으로 그걸 가리면 합계에서 실제 돈이 빠집니다. 자산현황에서 계정이 접히는 조건이 `잔액 0 **그리고** 종료됨`인 이유가 이것입니다: 기여도가 정확히 0인 행만 사라지므로 어떤 합계도 움직일 수 없고, 종료된 계정에 거래가 들어오면 행이 **다시 나타납니다**.
- 사용 기간은 어느 계정에 **쓸 수 있는지**를 정할 뿐, 무엇이 **쓰여 있을 수 있는지**는 제한하지 않습니다. 입력 폼·수정은 거래 날짜 기준으로 막지만(`app/entry-actions.ts`), CSV 가져오기는 어느 것도 막지 않습니다 — 백업에는 이미 해지한 계정의 과거가 들어 있고, 여기서 막으면 내보낸 파일을 되돌릴 수 없게 됩니다.
- 계정과목마다 통화를 지정할 수 있고, 섹션 기준통화로 환산해 보여줍니다. 장부가는 거래시점 환율로 고정되고, `환율 반영` 동작으로만 손익에 반영됩니다.
- 자산 합계·순자산은 **항상 장부가(거래시점 환율) 기준**입니다. 현재 환율로 평가한 값은 계정별 참고 표시일 뿐이며, 실제로 반영하려면 `환율 반영` 버튼으로 평가차액을 거래로 계상해야 합니다. 환율을 못 가져온 통화는 해당 계정에 `환율 없음`으로만 표시되고, 장부가 합계와 나머지 화면은 영향을 받지 않습니다.
- 서버·DB 저장은 UTC 고정이며, 거래 날짜 같은 달력 날짜는 타임존 없는 문자열로 저장합니다. 표시·기간 계산에만 섹션 타임존이 개입합니다.
